# 从面试官视角看「Agent 实习生」岗位：简历、回答与考察点

> 来源：B 站视频 BV1cZ8x6sEhF《作为 Agent 实习生的面试官，你们的简历和回答确实该挂！》（UP：xhyovo，2026-08-23，单 P，约 31 分钟）
> 内容为口播观点整理；转录由本地 FunASR Server 完成，个别专有名词（如"AI/AI Agent/coding"）存在同音误识别，理解时已按语境校正。

## 学完本节你应该获得什么

- 知道投「AI/Agent 实习」这类岗位时，简历与自我介绍为什么不能沿用传统开发模板，以及改写的两个出发点。
- 理解面试官为什么"不 care 你的项目"，以及他如何判断一个 GitHub 项目是伪造的。
- 拿到这位面试官固定考察的七类问题清单（工具差异、AI coding 工作流、常用 skills、Agent/harness/目标工程理解等），知道每类问题在考察什么、合格回答长什么样。
- 知道"能主动共享屏幕演示"为什么是决定性加分项，以及 AI 面试话术为什么骗不过有经验的面试官。

## 一句话总论

投 AI coding 相关岗位，你从头到尾要做的是**证明"为什么你适合这个岗位"**，而不是堆砌传统开发经历、玩具项目或背诵八股式流程——能力与岗位的偏差，才是大量候选人被挂的真正原因。

## 适用场景与前置知识

适用：正在投 AI/Agent/大模型应用类实习或初级岗位、准备面试话术，或想按"面试官视角"优化简历的人。前置知识：了解 Claude Code/Codex/Cursor 等至少一种 AI coding 工具；写过简单项目；知道 Git、需求/PRD、代码 review 的基本概念即可。

## 知识地图

1. 简历与自我介绍：围绕岗位职责改写，去掉传统开发噪音
2. 项目：为什么不被看重、什么情况下会被追问、伪造如何被识破
3. 面试前两分钟：自我介绍与"展示作品能力"的决定性作用
4. 必问七类考察点：AI 工具差异 / 个人 AI coding 工作流 / 常用 skills 与理解深度 / AI 思维（Agent、harness 工程、目标工程）
5. 候选人的准备姿势与收尾判断标准

## 核心概念卡

- **岗位映射（Job Mapping）**：JD 是 AI coding 相关，简历与自我介绍就只说 AI coding 相关的能力；传统 JAVA/前端/Go 的技术栈描述既不匹配也不被需要，反而暴露对 AI 的敏感度不足[1][2]。
- **玩具项目 / 伪造成本**：实习生项目在面试官眼里基本是玩具——上线但没人用依然是玩具[4]；而伪造项目（假 commit 历史、删注释/README 掩盖来源）用 AI 溯源即可识破，一旦识破"两分钟就挂"[4]。
- **AI 时代的两个核心能力**：系统架构设计与产品能力，语言/技术栈不重要[6]；判断项目该不该做成平台，正是它们的试金石[6]。
- **展示作品能力**：敢说"我可以共享屏幕演示"意味着自主学习强、确为自己所做、有自信、能把面试主动权从一问一答变成带节奏的展示，前两分钟即可定生死[5]。
- **Agent、harness 工程、目标工程**：Agent = 大模型 + 工具去解决问题；harness 工程 = 在模型外叠加思维链、记忆、自我沉淀、提示词等约束以提升质量，**不含新技术**；目标工程 = 只给目标、过程交给模型自我纠错与沉淀——这些概念"现在才火"不是因为技术新，而是模型能力变强[14]。

## 方法与流程：面试官必问的考察点与合格回答

他明说简历写得再好也会问同样的问题，目的是看表达能力和简历之外的东西[7]。按类别拆解：

1. **你真的用 AI coding 吗？用过哪些顶级工具、差异在哪**——考察对 Agent 本质的理解[7]。合格答案要能说出工具间差异：例如 Claude Code 遇到搜索/调研类 prompt 会主动调用 sub-agent（sandbox agent），Codex 则倾向直接使用主 agent[8]；要区分"工具"与"模型"——嫌贵可接便宜的模型（如 Claude Code 接 DeepSeek），但工具本身要用业界顶级[9]。
2. **你自己的 AI coding 工作流**——考察熟练度[9]。反例是只答"先需求分析、再写 plan、再 review"的车轱辘话/八股话[10]。合格答案要给具体落地链路：需求 → 用某需求分析 skill（如头脑风暴/spec 生成）产出 spec 文档 → 转成 plan 文档、拆给不同子 agent 执行 → 由 spec 转出验收标准（AC）供后续端到端测试 → 分阶段 review（功能正确性 review、规范与优雅设计 review、spec 偏差 review）→ git 管理 → 文档对齐与上下文沉淀[11][12]。
3. **你常用哪些 skills？为什么**——考察钻研度与深度[10]。能讲出常用 skills 说明平时在用、技术广度够；能评价某个 skill 是否该被淘汰（如对顶级模型，过度结构化的头脑风暴 skill 反而耗时）说明有独立思考[13]。
4. **AI 思维三连问：Agent / harness 工程 / 目标工程是什么**——考察是否跟进前沿且能触到本质，而不是背概念[14]。他本人对"目标工程"并不完全看好，但认为候选人要理解它为何出现[14]。

## 关键洞察

- 简历过了 ≠ 简历没问题：可能只是别的面试官筛的，简历到真正较真的面试官手里根本过不去[3]。
- 项目做得"多、大、花"都不加分；**AI 处理能力强 ≈ 能创造项目**，所以与其堆项目不如把 AI coding 能力练到能当堂对答[4][15]。
- 面很久才挂不是 KPI，而是"面试礼仪"式的混时长——几分钟挂说不过去，40 分钟挂不代表你有戏[3]。
- 背 AI 生成的话术骗不过他，但能共享屏幕现场演示且真答上来，他也认你是真本事[16]。

## 坑点与反例（他点名批评的）

- 简历大篇幅写 JAVA/前端/Go 等传统技术栈[1]。
- 自我介绍还在背传统开发经历，与 AI coding 岗位不匹配[2]。
- 用假 commit、删 README/注释企图掩盖"借鉴/伪造"的项目[4]。
- 把本该工具化/脚本化的东西做成"平台"：四位候选人三位写"运维制作平台"，属于架构设计能力缺陷的产物——平台要管 UI/前后端/用户体系，而运维助手本质是知识/资产类工具，应 skills 化而非流程化平台[6]。
- 面试只答"需求分析→plan→review"的流程八股，没有任何具体的 AI 用法与工具名[10]。

## 实践清单（看完可以直接做）

1. 按目标 JD 重写简历与 1 分钟自我介绍：只保留与 AI coding/Agent 相关的能力与经历。
2. 至少深度使用一款顶级 AI coding 工具（Claude Code/Codex/Cursor），亲手对比它们处理"搜索/调研型 prompt"的行为差异，形成一句话总结。
3. 把最近一次需求走一遍完整 AI 工作流：spec → plan/子任务拆分 → 验收标准 → 分阶段 review → git → 文档沉淀，并能在面试中讲出每个环节用的具体 skill。
4. 挑选 2-3 个自己最常用的 skills，想清楚每个解决什么问题、对顶级模型是否仍必要。
5. 为你的项目准备 5 分钟"共享屏幕"演示脚本：从真实需求出发讲清形态判断（为什么是工具/平台）与架构取舍。
6. 用 AI 自查简历里的项目：任何经不起 AI 溯源的东西一律删掉或如实标注"课程/学习项目"。
