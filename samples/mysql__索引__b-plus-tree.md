# B+ 树索引为什么快

InnoDB 的索引结构是 **B+ 树**。理解它，才能解释"为什么加了索引查询就快"。

## 为什么不是二叉搜索树

二叉搜索树在数据有序插入时会退化成链表，高度随数据量线性增长。B+ 树是**多路平衡树**，一个节点可以放多个键，树的高度保持在 2~4 层。

## B+ 树的结构

- 只有叶子节点存数据（或指向数据行的指针）
- 非叶子节点只存键，用于路由
- 叶子节点之间用链表相连，天然支持范围查询

```text
            [30]                <- 根节点（只存键）
          /      \
    [10, 20]      [40, 50]      <- 内部节点
    /  |  \       /  |  \
  (1)(15)(25)  (35)(45)(60)    <- 叶子节点（存数据 + 链表连接）
```

## 为什么快

| 特性 | 收益 |
|---|---|
| 高度低（3~4 层） | 每次查询只要 3~4 次磁盘 IO |
| 叶子链表 | 范围查询 `BETWEEN` / `>` 连续扫描 |
| 键有序 | 无需全表扫描，二分定位 |

```sql
-- 命中索引：走 B+ 树定位
SELECT * FROM users WHERE age = 28;

-- 范围查询：叶子链表顺序扫描
SELECT * FROM users WHERE age BETWEEN 20 AND 30;

-- 前缀列上的范围或模糊：索引失效（最左前缀）
SELECT * FROM users WHERE name LIKE '%张%';
```

## 常见坑

1. **最左前缀原则**：联合索引 `(a, b)` 上查 `b` 不会走索引。
2. **函数包住索引列**（`WHERE YEAR(created_at)=2026`）会让索引失效。
3. 区分度低的列（性别）做索引收益很小。
