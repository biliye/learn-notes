# 面试官视角：Agent 实习岗位的简历、回答与七类考察点

> 内容整理自 B 站视频《作为 Agent 实习生的面试官，你们的简历和回答确实该挂！》（UP：xhyovo，2026-08-23，约 31 分钟，[原视频](https://www.bilibili.com/video/BV1cZ8x6sEhF/)）。转录由本地语音识别完成，个别专有名词按语境校正；该观点含较强个人评价色彩，属单方面试官视角，不是岗位通用标准。

## 学完本节你应该获得什么

- 知道投 AI Agent / AI coding 岗位时，简历与自我介绍为什么不能沿用传统开发模板，以及改写的两个出发点。
- 理解面试官为什么"不 care 你的项目"、什么情况下他会追问项目、伪造的 GitHub 项目为何能被识破。
- 拿到一份该类岗位的高频考察清单（工具差异、AI coding 工作流、常用 skills、Agent/harness/目标工程理解），知道每一类在考察什么、合格回答长什么样。
- 理解"敢主动共享屏幕演示"为什么是决定性加分项，以及背 AI 话术为什么骗不过有经验的面试官。

## 一句话总论

投 AI coding 相关岗位，你从头到尾要证明的是"为什么你适合这个岗位"：与其堆传统开发经历、玩具项目或背诵流程八股，不如把真实的 AI 使用方式、思考过程和产出展示出来——能力与岗位的偏差，才是大量候选人被挂的真正原因。

## 适用场景与前置知识

适合正在投 AI/Agent/大模型应用类实习或初级岗位、准备面试，或想按"面试官视角"优化简历的人。前置知识：至少深度使用过一款 AI coding 工具（Claude Code、Codex、Cursor 等）；写过简单项目；了解 Git、需求分析与代码 review 的基本概念。

## 知识地图

1. 简历与自我介绍：围绕岗位职责改写，去掉传统开发噪音。
2. 项目：为什么不被看重、什么情况会被追问、伪造如何被识破。
3. 面试前两分钟：自我介绍与"展示作品能力"的决定性作用。
4. 高频考察点：AI 工具差异、个人 AI coding 工作流、常用 skills 与理解深度、AI 思维（Agent、harness 工程、目标工程）。
5. 候选人的准备姿势与收尾判断标准。

## 核心概念卡

**岗位映射（Job Mapping）**：JD 是 AI coding 相关，简历与自我介绍就只说 AI coding 相关的能力。传统 JAVA / 前端 / Go 的技术栈描述既不匹配也不需要，反而暴露你对 AI 的敏感度不足；面试前两分钟就能据此判挂。

**玩具项目与伪造成本**：实习生项目在面试官眼里基本是玩具——上线但没人用依然是玩具。伪造项目（假 commit 历史、删注释与 README 掩盖来源）用 AI 溯源即可识破，一旦识破基本直接挂掉。

**AI 时代的两个核心能力**：系统架构设计与产品能力，具体语言不重要。判断项目该不该做成平台，正是这两种能力的试金石：作者本人有真实运维需求，也只把自己的运维助手做成脚本/技能化工具，而非 Web 平台。

**展示作品能力**：敢主动说"我可以共享屏幕演示"，意味着作品确为自己所做、你熟悉它、有自信，并能把面试从一问一答变成你带节奏的展示——前两分钟就能奠定结果。

**Agent、harness 工程与目标工程**：Agent = 大模型 + 工具去解决问题；harness 工程 = 在模型之外叠加思维链、记忆、自我沉淀、提示词等约束以提升质量，本身不含新技术；目标工程 = 只给目标、过程交给模型自我纠错与沉淀。这些概念"现在才火"不是因为技术新，而是模型能力变强了。

## 方法与考察清单：高频问题与合格答法

作者明说简历写得再好也会问同一批问题，目的是看表达能力和简历之外的东西。以下是核心考察点与合格答案的形态。

**用过哪些顶级 AI coding 工具、差异在哪**——考察对 Agent 本质的理解。合格答案能说出工具间差异：例如 Claude Code 遇到搜索/调研类任务会主动调用沙箱子代理，Codex 则倾向直接用主代理完成。要区分"工具"与"模型"：嫌模型贵可以在 Claude Code 这类工具里接 DeepSeek 等便宜模型，但工具本身值得用业界顶级的，因为你未来做的 Agent 和它们本质同构。

**你自己的 AI coding 工作流**——考察熟练度。反面教材是只答"先需求分析、再写 plan、再 review"的车轱辘话。合格答案要给出可落地的链路：用某个需求分析 skill 产出 spec 文档 → 转成 plan 并拆给不同子代理执行 → 由 spec 转出验收标准供后续端到端测试 → 分阶段 review（功能正确性、代码规范与优雅性、与 spec 的偏差）→ git 管理与文档对齐沉淀。每步都要说出具体工具或 skill。

**你常用哪些 skills、为什么**——考察钻研度与深度。能讲出常用 skills 说明平时在用、技术广度够；能评价某个 skill 是否该被淘汰（例如对顶级模型，过度结构化的头脑风暴 skill 反而耗时）说明有独立思考。作者强调有些经验是"花钱烧出来的"：亲自上手不同模型，才能体会它们在能力边界上的差异。

**AI 思维三连问：Agent / harness 工程 / 目标工程**——考察你是否触到本质而非背概念。harness 工程里的思维链、提示词、记忆、自我沉淀两年前就有，并不高深；目标工程作者本人并不完全看好，但认为候选人要能理解这类概念为什么在模型变强后突然流行。

## 关键洞察

简历过了不等于简历没问题：可能只是别的面试官筛的，简历到了较真的面试官手里根本过不去，所以收到面试邀约也值得回头再审一遍简历。

项目做得"多、大、花"都不加分；AI 处理能力强约等于能创造项目。与其堆项目，不如把 AI coding 能力练到能当堂对答。

面很久才挂未必是 KPI 行为，也可能是面试官在按礼仪混时长——几分钟挂掉说不过去，聊满时长不代表你有戏。

背 AI 生成的话术骗不过有经验的面试官，但如果你能共享屏幕现场演示且真能答上来，他也认你是真本事。

## 坑点与反例

- 简历用大篇幅写 JAVA、前端、Go 等传统技术栈，与 AI coding 岗位不匹配。
- 自我介绍还在背传统开发经历，开场即与岗位职责脱节。
- 用假 commit、删 README 和注释企图掩盖借鉴或伪造的项目。
- 把本该工具化/脚本化的东西硬做成平台。例如把运维助手做成 Web 平台：平台要管 UI、前后端与用户体系，而运维助手本质是面向个人资产的知识型工具，应脚本化/技能化而非做成流程化平台。
- 面试只答"需求分析 → plan → review"的流程八股，没有任何具体的 AI 用法与工具名。

## 实践清单

1. 按目标 JD 重写简历与 1 分钟自我介绍，只保留与 AI coding / Agent 相关的能力与经历。
2. 至少深度使用一款顶级 AI coding 工具，亲手对比它在"搜索/调研型任务"上的行为，形成一句话总结。
3. 把最近一次需求完整走一遍 AI 工作流：spec → plan/子任务拆分 → 验收标准 → 分阶段 review → git → 文档沉淀，并能在面试中讲出每步用的具体 skill。
4. 挑选 2-3 个最常用的 skills，想清楚每个解决什么问题、对顶级模型是否仍然必要。
5. 为项目准备 5 分钟"共享屏幕"演示脚本：从真实需求出发，讲清形态判断（为什么是脚本/工具而非平台）与架构取舍。
6. 用 AI 自查简历里的项目，凡经不起 AI 溯源的内容一律删除或如实标注为课程/学习项目。

## 自测题

1. 投 AI coding 实习，简历里要不要保留大学做的 Java 后端项目？为什么？
2. 面试官说"我对你的项目不感兴趣"可能有哪些原因？什么时候他反而会追问项目？
3. Codex 与 Claude Code 在"需要调研"的任务上行为有何典型差异？这说明了什么？
4. 口述一条"从需求到上线"的 AI coding 工作流，要求每个环节出现具体工具或 skill 名。
5. "harness 工程里没有新技术"你认同吗？它和两年前的提示词、思维链工程差别在哪？
6. 面对"目标工程"，你会如何评价它的适用边界？

## 小结

这段视频真正想传递的判断标准很简单：实习生不需要做出成熟商业产品，概念理解也可以不成熟，但经历必须真实、思考必须独立、展示必须与岗位相关。面试官要看到的是你确实在用 AI 工作、有自己的工作流与想法，并且愿意把真实过程亮出来。
